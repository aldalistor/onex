# المرحلة الخامسة — التقارير المالية والطباعة

## ما تم تنفيذه

أضيفت طبقة تقارير مالية موحدة إلى الخادم وواجهة النوافذ. يحتوي فهرس التقارير الحالي على ثلاثة تقارير تشغيلية مرتبطة ببيانات النظام:

| الرمز | التقرير | المصدر |
|---|---|---|
| `GLSR001` | ملخص القيود المحاسبية | `journal_entries` |
| `ARSR041` | سجل فواتير المبيعات | `invoices` |
| `MRPREP001` | تقييم المخزون | `stock_balances` |

يقدم الخادم عقد `reports.catalog` لفهرس التقارير، وعقد `reports.run` لتشغيل التقرير مع بحث اختياري وحد أقصى للصفوف. عند وجود `DATABASE_URL` وتفعيل `ONEX_USE_DATABASE=1`، تُقرأ النتائج من الجداول الفعلية. في وضع التطوير دون قاعدة بيانات، يستخدم النظام fallback محدودًا وواضحًا.

## الطباعة والتصدير

أضيفت إلى نوافذ التقارير معاينة جدولية تعرض عنوان التقرير ومصدره وعدد السجلات. يستطيع المستخدم طباعة التقرير عبر `window.print()` مع CSS مخصص يخفي عناصر التشغيل غير اللازمة. كما يستطيع تصدير النتيجة إلى ملف CSV بترميز UTF-8 مع BOM لدعم Excel واللغة العربية.

## النوافذ المرتبطة

تستخدم `ARSR041` تقرير فواتير المبيعات، وتستخدم `MRPREP001` تقييم المخزون، بينما تستخدم نوافذ تقارير GL مثل `GLSR001` ملخص القيود المحاسبية. تم الحفاظ على نمط النوافذ القديم وشريط الأدوات الموحد.

## الحدود

هذه المرحلة تنفذ تقارير تشغيلية أساسية من المخطط المحلي. لا تزال تقارير RDF الأصلية البالغ عددها 6,613 تقريرًا بحاجة إلى ربط فردي بقواعد البيانات وبارامترات Oracle الخاصة بها. كما أن PDF الرسمي والتنسيق الطباعي المطابق لكل تقرير RDF سيكون ضمن مرحلة لاحقة بعد اعتماد قوالب التقارير.

## التحقق

نجح فحص TypeScript. نجحت اختبارات المشروع وعددها 16 اختبارًا. اكتمل بناء الإنتاج مع تحذيرات غير مانعة مرتبطة بمتغيرات التحليلات وحجم حزم Mermaid الموجودة سابقًا.

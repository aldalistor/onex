# المتطلبات الوظيفية من كتيب OnyxPro وربطها بالنواة

## مصدر المتطلبات

المصدر هو `OnyxPro_System.pdf` المرفق سابقًا، وعدد صفحاته 26 صفحة. الكتيب يصف وظائف الإصدار 2.1 لعام 2009، لذلك يستخدم كمرجع وظيفي وتناسق شاشات، بينما تُحسم التفاصيل التنفيذية الأحدث من FMX/PLX وOracle Test DB.

## مبادئ التناسق مع النظام الأصلي

يجب أن تحتفظ النسخة المحدثة باسم النافذة القديم، وترتيب الرأس والتفاصيل، وقواعد الصلاحية، وحالات المستند، وأثر الترحيل. يمكن تحديث الألوان والخطوط والتوافق مع الشاشات الحديثة، لكن لا يتغير معنى الحقول أو تسلسل العملية دون موافقة مالك الأعمال.

## الوظائف العامة

| الوظيفة في الكتيب | التصميم المحدث | الذرية |
|---|---|---|
| عدد نسخ الطباعة | Printing Profile مرتبط بالمستخدم/التقرير | حفظ إعداد كامل أو لا شيء |
| تخصيص التقارير | Report Definition ونسخة إعداد | تحديث ذري مع تدقيق |
| تصدير الدليل والأصناف والعملاء والموردين إلى Excel | Export Job من Outbox | لا يغير البيانات المصدر |
| فتح أكثر من شاشة وفرع ومركز | Session Context وRow-Level Security | إنشاء Context كامل قبل العملية |
| شجرة الدليل المحاسبي | Account Tree مع حسابات ومراكز تكلفة | نشر نسخة شجرة كاملة |
| التوقيعات | Approval Matrix | تغيير حالة المستند مرة واحدة |
| الشاشة الرئيسية للتنبيهات والاستحقاقات | Dashboard Queries وDue Schedule | قراءة فقط |
| متغيرات النظام وNo_Database | System Parameters | تعديل ذري ومدقق |

## إدارة الحسابات

تشمل النواة:

- العملات والصناديق والبنوك.
- التسويات البنكية.
- القيود الآلية.
- التفقيط حسب الحساب والعميل والمركز والعملة.
- شجرة الدليل والحسابات ومراكز التكلفة.
- صلاحيات F9 وTAB.
- فترة السماح للمستخدم.
- سجل الإدخال وآخر تعديل.
- منع تعديل أو إلغاء المستند إلا بحركة لاحقة أو عكس رسمي.

كل عملية مالية تمر عبر `ONEX_ATOMIC_API` وتكتب Audit Event داخل نفس المعاملة.

## المبيعات والعملاء وAR

تشمل الوظائف:

- فاتورة البيع ومردود البيع.
- آخر عشر حركات للصنف والعميل.
- حدود الأسعار والكميات.
- قائمة العملاء السوداء.
- تجميع عمليات بيع متعددة.
- عروض الأسعار وطلبات العملاء.
- تواريخ التسليم والتحضير.
- المندوب والمحصّل والحوافز والعمولات.
- الكميات المجانية.
- التسويات والخصومات.
- حدود الدين والحد الائتماني.
- خطط التحصيل والاستحقاقات.

الربط الأساسي:

```text
ARST004 → ONEX_AR_WINDOW_API.CREATE/POST
ARST006 → ONEX_AR_WINDOW_API.REVERSE
ARST023 → Approval Matrix + ONEX_AR_DUE
ARSR041 → Customer balances and collection plans
```

يجب أن تكون حركة المخزون مرتبطة بمصدر المستند ومفتاح Idempotency، وتُرفض إذا نتجت كمية غير صالحة أو تعارض قفل.

## التوافق مع النوافذ الأصلية

سجل `ONEX_WINDOW_REGISTRY` يسجل كل نافذة من 1,490 نافذة. الحالة لا تنتقل من `SPEC_ONLY` إلى `GOLDEN_MASTER_VERIFIED` إلا بعد اختبار العملية نفسها في Forms القديم والنسخة الجديدة ومقارنة:

- المخرجات.
- الأرصدة.
- القيود.
- حركة المخزون.
- الاستحقاقات.
- الصلاحيات.
- سجل التدقيق.

## ما لا يثبته PDF وحده

الكتيب لا يثبت أسماء الجداول أو توقيعات Packages أو كل Triggers. لذلك تُستخدم أسماء Forms وSQL من FMX لتكوين المرشحين، ثم تُؤكد من `DBA_ARGUMENTS`, `DBA_SOURCE`, وDDL قاعدة الاختبار قبل كتابة كود تنفيذي.
